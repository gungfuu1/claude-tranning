# Spec 003 — สมัครสมาชิกและเข้าสู่ระบบ (R1)

## 1. Goal

ผู้เยี่ยมชมสมัครสมาชิกได้เองภายใน 2 นาที โดยระบุว่าเป็นพนักงาน กฟภ. หรือบุคคลภายนอก เพื่อให้ระบบรู้ว่าลงทะเบียนหลักสูตรใดได้บ้าง สมาชิกเข้าสู่ระบบด้วยอีเมลและรหัสผ่าน แล้วกลับไปหน้าที่เปิดค้างไว้เพื่อทำต่อได้ทันที ระบบต้องกันการเดารหัสผ่านและไม่เปิดเผยว่าอีเมลใดมีบัญชีอยู่

## 2. Scope

**อยู่ในขอบเขต:** หน้าสมัครสมาชิก `/register`, หน้าเข้าสู่ระบบ `/login`, การออกจากระบบ, การล็อกบัญชีเมื่อ login ผิดติดต่อกัน, การกลับไปหน้าเดิมด้วย `?next=`, การขอความยินยอมตาม PDPA ตอนสมัคร, ลิงก์ "เข้าสู่ระบบ" และ "สมัครเรียน" ในเมนูหลัก

**อยู่นอกขอบเขต:** ลืมรหัสผ่าน/ตั้งรหัสผ่านใหม่, ยืนยันอีเมลก่อนใช้งาน, login ด้วยบัญชีภายนอก (Google, ระบบ HR), แก้ไขโปรไฟล์, ตรวจรหัสพนักงานกับระบบ HR, การกำหนด role `ADMIN` (อยู่ใน R10)

## 4. Business Rules

กติกา BR ใช้รหัสเดียวกับ `system_requirement.md` เพื่อให้ trace ได้ ส่วน REG-xx เป็นกติกาที่ spec นี้เพิ่ม

| รหัส | กติกา | Error code |
|---|---|---|
| BR-01 | ชื่อ-นามสกุลยาว 2–100 ตัวอักษร นับหลังตัดช่องว่างหน้า-หลัง | `VALIDATION_FAILED` |
| BR-02 | อีเมลต้องถูกรูปแบบและไม่ซ้ำในระบบ เปรียบเทียบแบบไม่สนตัวพิมพ์และหลังตัดช่องว่างหน้า-หลัง | `EMAIL_TAKEN` |
| BR-03 | รหัสผ่านยาวอย่างน้อย 8 ตัวอักษร และช่องยืนยันต้องตรงกัน | `VALIDATION_FAILED` |
| BR-04 | `EMPLOYEE` ต้องกรอกรหัสพนักงานเป็นตัวเลข 6 หลักที่ไม่ซ้ำ และเลือกสังกัด ส่วน `PUBLIC` ไม่ต้องกรอก และระบบไม่บันทึกค่านี้แม้มีส่งมา | `EMPLOYEE_ID_TAKEN` |
| BR-05 | `EMPLOYEE` ต้องใช้อีเมลโดเมน `@pea.co.th` | `EMPLOYEE_EMAIL_REQUIRED` |
| BR-06 | login ผิดติดต่อกัน 5 ครั้งล็อกบัญชี 15 นาที ระหว่างล็อกแม้รหัสถูกก็เข้าไม่ได้ login สำเร็จแล้วตัวนับกลับเป็น 0 | `ACCOUNT_LOCKED` |
| BR-07 | หลัง login กลับไปตาม `?next=` ได้เฉพาะ path ภายในเว็บ ค่าอื่นกลับหน้าแรก `/` | – |
| REG-01 | ต้องติ๊กยินยอม PDPA จึงสมัครได้ ระบบบันทึกเวลาที่ให้ความยินยอม | `CONSENT_REQUIRED` |
| REG-02 | อีเมลหรือรหัสผ่านผิดแสดงข้อความเดียวกัน "อีเมลหรือรหัสผ่านไม่ถูกต้อง" ไม่บอกว่าผิดช่องไหน และไม่บอกว่าอีเมลนั้นมีบัญชีหรือไม่ | `INVALID_CREDENTIALS` |
| REG-03 | กรอกผิดแล้วข้อมูลที่กรอกไว้ยังอยู่ ยกเว้นช่องรหัสผ่านและยืนยันรหัสผ่าน | – |
| REG-04 | ระบบไม่เก็บรหัสผ่านในรูปที่อ่านย้อนกลับได้ และไม่แสดงรหัสผ่านในข้อความ error หรือ log | – |
| REG-05 | ทุกกติกาข้างต้นตรวจที่ฝั่งระบบ (server) เสมอ การตรวจบนหน้าจอเป็นเพียงความสะดวกของผู้ใช้ | – |

**ความหมายของ "path ภายใน" (BR-07):** ขึ้นต้นด้วย `/` ตัวเดียว ไม่ขึ้นต้นด้วย `//` หรือ `/\` และไม่มี scheme เช่น `http:` หรือ `javascript:`

## 5. Acceptance Scenarios

### สมัครสมาชิก (US-01)

**AS-01 สมัครเป็นบุคคลภายนอกสำเร็จ** (BR-01, BR-03, REG-01)
- Given อยู่หน้า `/register` และเลือก "บุคคลภายนอก"
- When กรอกชื่อ `สมชาย ใจดี` อีเมล `somchai@example.com` รหัสผ่าน `abcd1234` สองช่องตรงกัน ติ๊กยินยอม แล้วกดสมัคร
- Then ได้บัญชีประเภท `PUBLIC` อยู่ในสถานะ login แล้ว และไปหน้าตาม `?next=` หรือ `/`

**AS-02 สมัครเป็นพนักงานสำเร็จ** (BR-04, BR-05)
- Given เลือก "พนักงาน กฟภ."
- When กรอกอีเมล `somchai.j@pea.co.th` รหัสพนักงาน `501234` เลือกสังกัด และข้อมูลอื่นถูกต้อง
- Then ได้บัญชีประเภท `EMPLOYEE` ที่บันทึกรหัสพนักงานและสังกัด

**AS-03 ตรวจข้อมูลที่กรอก** (BR-01, BR-03)

| ข้อมูลที่กรอก | ผล |
|---|---|
| ชื่อ `ก` (1 ตัว) | ไม่ผ่าน |
| ชื่อ `  กข  ` (2 ตัวหลังตัดช่องว่าง) | ผ่าน |
| ชื่อยาว 100 ตัว / 101 ตัว | ผ่าน / ไม่ผ่าน |
| ชื่อเป็นช่องว่างล้วน | ไม่ผ่าน |
| อีเมล `somchai@` | ไม่ผ่าน |
| รหัสผ่าน 7 ตัว / 8 ตัว | ไม่ผ่าน / ผ่าน |
| รหัสผ่าน `abcd1234` ยืนยัน `abcd1235` | ไม่ผ่าน "รหัสผ่านไม่ตรงกัน" |

**AS-04 อีเมลซ้ำ** (BR-02)
- Given มีบัญชี `somchai@example.com` อยู่แล้ว
- When สมัครด้วย `Somchai@Example.com` หรือ `  somchai@example.com  `
- Then สมัครไม่ได้ และแสดง "อีเมลนี้ถูกใช้แล้ว"

**AS-05 กติกาเฉพาะพนักงาน** (BR-04, BR-05)

| กรณี (เลือก "พนักงาน กฟภ.") | ผล |
|---|---|
| รหัสพนักงานว่าง หรือไม่เลือกสังกัด | ไม่ผ่าน ช่องนั้นแสดงว่าต้องกรอก |
| รหัสพนักงาน `12345` (5 หลัก) / `1234567` (7 หลัก) / `12A456` | ไม่ผ่าน |
| รหัสพนักงาน `012345` | ผ่าน (เลข 0 นำหน้าถูกเก็บไว้) |
| รหัสพนักงานที่มีผู้ใช้อื่นใช้แล้ว | ไม่ผ่าน "รหัสพนักงานนี้ถูกใช้แล้ว" |
| อีเมล `somchai@gmail.com` | ไม่ผ่าน "พนักงานต้องใช้อีเมล @pea.co.th" |
| อีเมล `somchai@PEA.CO.TH` | ผ่าน (โดเมนไม่สนตัวพิมพ์) |
| อีเมล `somchai@sub.pea.co.th` หรือ `somchai@pea.co.th.evil.com` | ไม่ผ่าน |

**AS-06 บุคคลภายนอกไม่มีข้อมูลพนักงาน** (BR-04)
- Given เลือก "บุคคลภายนอก"
- Then ไม่เห็นช่องรหัสพนักงานและสังกัด
- When ส่งข้อมูลที่มีรหัสพนักงานแนบมาด้วยโดยตรง (ไม่ผ่านหน้าจอ)
- Then สมัครได้ และบัญชีไม่มีรหัสพนักงานหรือสังกัดบันทึกไว้

**AS-07 ไม่ยินยอม PDPA** (REG-01)
- When ไม่ติ๊กยินยอมแล้วกดสมัคร
- Then สมัครไม่ได้ และแสดง "กรุณายอมรับนโยบายความเป็นส่วนตัว"

**AS-08 กรอกผิดแล้วข้อมูลไม่หาย** (REG-03)
- When สมัครไม่ผ่านด้วยเหตุผลใดก็ตาม
- Then ช่องที่กรอกไว้ทั้งหมดยังมีค่าเดิม ยกเว้นรหัสผ่านและยืนยันรหัสผ่านที่ถูกล้าง
- And ข้อความ error แสดงใต้ช่องที่ผิด และอ่านออกด้วย screen reader

### เข้าสู่ระบบ (US-02)

**AS-09 login สำเร็จ**
- Given มีบัญชี `somchai@example.com` รหัสผ่าน `abcd1234`
- When login ด้วย `  SOMCHAI@example.com ` และรหัสผ่านถูก
- Then เข้าสู่ระบบได้ และเมนูหลักแสดงชื่อผู้ใช้

**AS-10 ข้อความเมื่อ login ไม่ผ่าน** (REG-02)

| กรณี | ข้อความ |
|---|---|
| อีเมลถูก รหัสผ่านผิด | อีเมลหรือรหัสผ่านไม่ถูกต้อง |
| อีเมลไม่มีในระบบ | อีเมลหรือรหัสผ่านไม่ถูกต้อง |

**AS-11 ล็อกบัญชี** (BR-06) บัญชีเดียวกัน เวลาไทย

| เหตุการณ์ | ผล |
|---|---|
| 10:00 ถึง 10:04 รหัสผิด 4 ครั้ง | ยังไม่ล็อก |
| 10:05 รหัสผิดครั้งที่ 5 | ล็อก แสดง "บัญชีถูกล็อกชั่วคราว กรุณาลองใหม่อีกครั้งใน 15 นาที" |
| 10:10 รหัสถูก | เข้าไม่ได้ ยังล็อกอยู่ |
| 10:20 รหัสถูก | เข้าได้ ตัวนับกลับเป็น 0 |

**AS-12 ตัวนับรีเซ็ตเมื่อ login สำเร็จ** (BR-06)
- Given รหัสผิดติดต่อกัน 4 ครั้ง แล้ว login สำเร็จ
- When รหัสผิดอีก 4 ครั้ง
- Then บัญชียังไม่ถูกล็อก

**AS-13 กลับไปหน้าเดิม** (BR-07)

| `?next=` | หลัง login ไปที่ |
|---|---|
| `/courses/SAF-101` | `/courses/SAF-101` |
| `/my-courses?tab=active` | `/my-courses?tab=active` |
| ไม่มี / ค่าว่าง | `/` |
| `https://evil.com` | `/` |
| `//evil.com` | `/` |
| `/\evil.com` | `/` |
| `javascript:alert(1)` | `/` |
| `courses` (ไม่ขึ้นต้นด้วย `/`) | `/` |

**AS-14 login อยู่แล้ว**
- Given login แล้ว
- When เปิด `/login` หรือ `/register`
- Then ไปหน้าตาม `?next=` (ตามกติกา BR-07) หรือ `/`

**AS-15 ออกจากระบบ**
- When กด "ออกจากระบบ"
- Then กลับหน้า `/` เมนูหลักแสดง "เข้าสู่ระบบ" และ "สมัครเรียน" และหน้าที่ต้อง login เปิดไม่ได้จนกว่าจะ login ใหม่

### ทั่วไป

**AS-16 รหัสผ่านไม่รั่ว** (REG-04)
- Then ไม่มีรหัสผ่านปรากฏใน URL ข้อความ error หรือ log และเก็บในรูปที่อ่านย้อนกลับไม่ได้

**AS-17 การเข้าถึงและมือถือ**
- Then หน้า `/register` และ `/login` ตรวจด้วย axe แล้วไม่มี violation ระดับ `serious` หรือ `critical`
- And ทุกช่องมี label และกรอกด้วยคีย์บอร์ดได้ครบ
- And ที่ความกว้าง 375 px ไม่มี scroll แนวนอน

## 6. Decisions

| ประเด็น | การตัดสินใจ | เหตุผล |
|---|---|---|
| สมัครเสร็จแล้วทำอะไรต่อ | เข้าสู่ระบบให้อัตโนมัติ และไปหน้าตาม `?next=` | ผู้ใช้ส่วนใหญ่มาสมัครเพราะจะลงทะเบียนหลักสูตรที่เปิดอยู่ ไม่ควรให้ login ซ้ำ |
| ยืนยันอีเมลก่อนใช้งาน | ไม่ทำในรอบนี้ | requirement ไม่ได้กำหนด การคัดกรองผู้เรียนทำผ่านการอนุมัติของ admin อยู่แล้ว |
| ข้อความตอนบัญชีถูกล็อก | แสดงว่าล็อก (ต่างจากข้อความรหัสผิด) | requirement มี error code `ACCOUNT_LOCKED` ผู้ใช้จริงต้องรู้ว่าต้องรอ ยอมรับว่าเปิดเผยว่าอีเมลนั้นมีบัญชี เฉพาะหลังผิดครบ 5 ครั้ง |
| login ผิดระหว่างถูกล็อก | ไม่นับเพิ่มและไม่ต่อเวลาล็อก | ป้องกันไม่ให้คนอื่นล็อกบัญชีเจ้าของไว้ได้ตลอด |
| อีเมลที่ไม่มีบัญชี | ไม่มีตัวนับและไม่ล็อก | ไม่มีบัญชีให้ล็อก และตอบเหมือนรหัสผิดตาม REG-02 |
| เก็บอีเมลแบบไหน | เก็บแบบตัวพิมพ์เล็กหลังตัดช่องว่าง | ทำให้ BR-02 และการ login ไม่สนตัวพิมพ์ตรงกันทุกที่ |
| ความยาวรหัสผ่านสูงสุด | ไม่กำหนดใน spec | requirement กำหนดเฉพาะขั้นต่ำ ถ้าวิธีเก็บมีขีดจำกัดให้ระบุใน plan |
